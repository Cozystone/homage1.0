# 지각 효율 — 뇌의 원리를 ATANOR 지각으로 (Predictive Perception)

사장님 질문: *"인간은 어떻게 오감으로부터 거의 무한·실시간의 정보를 받으면서도 부하·속도저하·용량초과 없이 처리하지?"*

핵심은 사장님이 스스로 짚으신 문장에 있습니다 — **"전부 처리해서 빠른 게 아니라, 대부분을 무시해서 빠른 것."** 이걸 우리 지각 스택의 설계 원리로 그대로 옮깁니다.

---

## 1. 뇌가 쓰는 4가지 절약 기제 → 우리 구현

| 생물학적 기제 | 사실 | ATANOR 구현 | 상태 |
|---|---|---|---|
| **감각기관 선(先)압축** | 망막 광수용체 ~1억 → 시신경 ~100만 (100:1 압축이 뇌 이전에 일어남) | `attention.frame_signature` — 프레임을 32×32 그레이 코드로 즉시 축약. 대부분의 픽셀은 무거운 모델이 보기 전에 버려짐 | ✅ SHIPPED |
| **예측 부호화(predictive coding)** | 피질은 장면을 예측하고 **예측 오차**(바뀐 부분)에만 연산을 씀 | `attention.decide` — 신규 코드 vs 마지막 코드의 변화 에너지를 재고, 장면이 실제로 바뀌어 **안정될 때만** OWLv2를 돌림. 정적 장면 = GPU ~0 | ✅ SHIPPED |
| **선택적 주의(ROI)** | 중심와(fovea)로 중요한 곳만 고해상 처리 | 변화가 일어난 영역만 잘라 그 crop에만 탐지 (v2) | ◻ 설계됨 |
| **병렬·계층 처리** | 시각·청각·운동 영역 동시 가동 | 저비용 상시 레인(움직임/사람 유무) + 고비용 간헐 레인(개방어휘 탐지) + 개념 레인(그래프/웹학습) 분리 | ◻ 부분 |

**결과**: 연산의 바닥은 **프레임레이트가 아니라 "변화량"이 결정**합니다. 장면이 안 바뀌면 거의 공짜, 바뀌면 그 순간 정확히 한 번 무겁게 — "가볍게, 성능 로스 없이"의 정확한 의미입니다.

---

## 2. 이번에 착지한 것: Predictive Attention Gate

`packages/perception/attention.py` (No-LLM, 순수 numpy, 결정론적 → 모델 없이 단위검증):

- `frame_signature(rgb)` — 망막 압축. 프레임 → 32×32 정규화 코드.
- `change_energy(a,b)` — 예측 오차. 두 코드의 평균절대차 [0,1].
- `decide(state, sig)` — 언제 무거운 탐지를 돌릴지 결정:
  - `cold_start` (첫 프레임) → 탐지
  - `moving_wait` (변화 큼 = 움직이는 중, 흐릿함) → **대기**(탐지 안 함)
  - `settled` (움직임이 잦아듦) → **그때 탐지** (선명한 새 장면을 잡음)
  - `refresh` (정적이어도 최소 6초마다 1회) → 느린 드리프트 안전망
  - `predicted` (정적) → **스킵**, 직전 판독 재사용
- `next_interval_s` — 클라이언트가 한가하면 느리게, 바뀌면 빠르게 폴링하도록 주의 배분 힌트 반환

`/api/perception/scene-ingest`에 배선 완료: 정적 프레임은 마지막 판독을 재사용(≈0 GPU), 변화가 안정되면 완전 탐지. 단위검증 7종 통과 — *60프레임 정적 장면에서 탐지는 ≤12회*(콜드스타트+주기 refresh)만 발화, 60회가 아님.

## 3. 사장님이 주신 나머지 방향 → 정렬된 진격로

1. **연산을 PC로, 웹캠은 얇게 (웹캠이 자꾸 죽는 문제)** — 현재 브라우저가 MediaPipe 무거운 모델을 매 프레임 메인스레드에서 돌려 카메라 스트림을 굶김. 브라우저를 **캡처→전송→박스 그리기**만 하는 얇은 클라이언트로 바꾸고 탐지는 PC(:8502 GPU)가 전담 → 메인스레드 부하 급감 = 스트림 생존. *(다음, 사장님 웹캠에서 검증 필요)*
2. **연속 자세 맥락 (11종 열거가 아니라)** — 관절 각·사지 위치·속도의 **연속 기하 서술자**를 뽑아 장면 맥락 문장에 합성. "arms_raised" 같은 분류표가 아니라 "한 손을 들어 화면을 가리키는 중" 같은 연속 서사.
3. **세상 학습 (웹 자가탐색: 유튜브·커뮤니티)** — 개념 레인을 기존 웹-파견 루프로 채움. 텍스트뿐 아니라 페이지/영상 자막을 증류해 개념 그래프에 접지. **환각 0 원칙 유지** — 본 것만 그래프로, 지어내지 않음.
4. **자기 최적화 (코드를 배웠으니)** — 게이트 임계값(_CHANGE_HI/LO, _MAX_SKIP_S)을 code_evolver의 탐색공간으로 열고, **검증 가능한 목적함수**(지연↓ × 탐지 안정성↑)에 대해 스스로 튜닝. 전면 재작성이 아니라 작고 검증가능한 함수만 — 정직한 경계 내 RSI.

---

## 4. 정직한 범위

- ✅ 지금 실재: 망막 압축 + 예측 부호화 게이트 (단위검증 + 라이브 배선).
- ◻ 설계·다음: ROI 주의, 얇은 클라이언트, 연속 자세, 웹 개념학습, 게이트 자기튜닝.
- 이 문서는 마케팅이 아니라 설계 근거입니다. "옴니버스급" 같은 수사 대신, 뇌가 쓰는 실제 절약 기제를 코드로 옮기는 것이 목표입니다.
