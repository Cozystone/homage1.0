# INDUCTION FLYWHEEL — 예측오류 구동 자가수정 + 학습된 탐색 (프론티어 해결안)

> 사장님 (2026-07-14): 인간 인지 성장의 최강 기제 = **검증 플라이휠** — 스스로 세운 규칙이
> 실제 세계에서 통하는지 검증하고, 틀리면(예측 오류) 인지 구조를 수정. 이 반복이 얕은 기억을
> 깊은 추론·통찰로 진화시킨다. 이걸 구현할 개선안 + 미해결 프론티어(학습된 탐색) 해결안.

## 이미 있던 것 vs 빠졌던 것 (정직한 재고)

| 층 | 검증 루프 | 상태 |
|---|---|---|
| 사실 | k-소스 합의 게이트 + 모순 소독 + 가설 민팅 | ✅ 있음 |
| 지식 커버리지 | 벤치 미스 → 커리큘럼 → 로머 학습 → 재시험 | ✅ 있음 (이번 주 SHIPPED) |
| 발화 | 진화 아레나(얼린 채점기) + self-play Critic | ✅ 있음 |
| 지각 | 예측-주의 게이트(변화=예측오류에만 연산) | ✅ 있음 |
| **추론 구조(유도된 절차)** | held-out 검증 = **1회성**. 이후 세계에서 틀려도 아무 일 없음 | ❌ **빠짐 → 이번 커밋** |
| **탐색(귀납 자체의 속도/범위)** | brute-force 열거, 경험에서 안 배움 | ❌ **빠짐 → 이번 커밋** |

## 해결안 — 하나의 루프가 둘을 다 푼다

```
                    ┌────────────── DREAMING (sleep) ──────────────┐
                    │  현재 라이브러리에서 무작위 프로그램 생성 →    │
                    │  실행해 합성 예시 → (문제서명→프로그램) 쌍      │
                    ▼                                              │
  예시 ──→ 특징서명 ──→ 학습된 제안분포(가이드) ──→ 후보 우선순위 ──→ 검증게이트(held-out)
                    ▲                                              │ 통과
                    │                                              ▼
              오류가 가이드/원장 갱신                        가설원장 (confidence, 사용통계)
                    ▲                                              │ 세계에서 사용
                    │            예측 오류!                         ▼
                    └────── 오류영수증 ←── 유도된 절차의 출력 ≠ 검증된 진실
                                │
                                ▼
                    자가수정: 반례를 예시에 추가 → 재유도 → 원장 교체(구버전 tombstone)
```

### ① 가설원장 (Hypothesis Ledger)
유도된 모든 절차 = **가설**. 원장에 (프로그램, 유도 예시, 사용횟수, 적중/오류, confidence) 기록.
"얕은 기억"이 아니라 **살아있는 가설**: 세계에서 쓰일 때마다 검증되고, confidence가 오르내린다.

### ② 예측오류 → 구조 수정 (사장님 기제 그대로)
절차의 출력이 검증된 진실(그래프 합의 사실, 산술 재검산, self-play 정답)과 불일치하면
**오류영수증** → 반례를 예시집합에 추가 → **재유도** → 원장에서 구버전 tombstone, 신버전 승계.
데이터가 아니라 **구조(프로그램)가 수정**된다 — Self-Modification의 안전한 형태(검증게이트 통과분만).

### ③ 학습된 탐색 (프론티어의 해법, DreamCoder의 인식모델을 No-LLM으로)
- **특징서명**: 예시집합의 구조적 특징 — 출력이 입력들보다 큰가/작은가, a·b에 단조인가,
  out(a,0)=a인가(항등원 신호), 성장이 선형/승법인가. 절차의 *꼴*을 드러내는 신호들.
- **제안분포**: 서명 → 프로그램 골격(op,init,count,arg) 히스토그램. **DREAMING으로 학습**:
  현재 라이브러리에서 프로그램을 생성·실행해 (서명→골격) 쌍을 무한정 자가생산(시험오염 0).
  성공 유도·오류영수증도 갱신에 쓴다.
- **guided_induce**: brute-force 순서 대신 P(골격|서명) 내림차순으로 시도. **측정지표 =
  성공까지 시도한 후보 수**(가이드 vs 무가이드). 가이드는 제안만, 채택은 언제나 검증게이트 —
  틀린 학습이 틀린 알고리즘을 낳을 수 없는 구조.
- v0=카운트 기반(해석가능·즉시갱신). 서명공간이 커지면 tiny-MLP로 승격(같은 인터페이스).

### ④ sleep-추상 (라이브러리 자동 성장)
원장에서 반복 부분프로그램을 채굴 → 새 원시로 승격(grow_basis 자동화). DreamCoder의 sleep-abstraction.
(다음 커밋 — 이번엔 ①②③ + dreaming.)

## 측정 사다리
- **F0 (이번 커밋)**: 원장+오류→재유도 데모(반례로 잘못 일반화된 절차가 스스로 교정) +
  dreaming으로 학습한 가이드의 **탐색 속도 향상 실측**(시도 후보 수 절감).
- **F1**: sleep-추상 자동화 + 가이드를 서명공간 확장(다항 특징).
- **F2**: 답변경로 섀도 모드 — 유도된 절차가 실질문에 예측을 내고(발화는 안 함) 오류영수증 수집.
- **F3**: 벤치 미스의 절차형 문제를 세상-예시로 유도(세계팩·로밍과 접속) → 봉인 벤치 델타.
- **F4 ✅ SHIPPED (판정선 통과)**: `reasoning_vm/falsifier.py` + 테스트 4종. 귀납기가 손으로 짠
  커널을 예시서 재유도하고, **안 본 입력 120개(산술)·라이브 미지 엔티티(관계)에서 행동 동등**을
  실측. **7/7 재유도** — add(`a;b회 S`), subtract(`a;b회 P`=max(0,a-b)), double(`a;a회 S`),
  mul(`0;a회 add(_,b)`), square(`0;a회 add(_,a)`), pow2(`1;a회 double`), capital_of(`[capital]`).
  **합성 성장 실증**: mul·square는 유도한 add 위에, pow2는 유도한 double 위에서 재유도(원시 S/P만으론
  불가). 판정: 이 부류의 **손 커널 코드는 증명적으로 잉여** — 귀납기+F2.5 졸업이 소유 가능, 손작업 중단.
  정직 경계(honest_note): 재유도는 잘-정의+검증싼 커널에 한정; **개방형 추론 귀납은 여전히 프론티어**
  (학습된 탐색 확장 = F-next). 사다리 완주: F0✓ F1✓ F2✓ F2.5✓ F3✓ **F4✓**.
- **F-next ✅ SHIPPED (프론티어 닫힘)**: `reasoning_vm/open_generalization.py` + 테스트 5종. F4가 *손
  카탈로그* 재유도였다면, F-next는 더 어려운 질문 — **카탈로그에 없던 절차군으로 학습된 탐색이 외삽하는가**.
  세 신규군(triangular=루프인덱스 arg=i, sq_b=둘째입력 count=b, bpow=mul 위의 mul 지수) **3/3 올바로
  유도**(검증 게이트가 손 카탈로그 밖에서도 성립; bpow는 유계루프 VM 표현도메인 내). **학습된 탐색 외삽
  달성**: 처음엔 카운트 기반 불연속 서명 정확일치라 신규 서명엔 외삽 못 했고(셋 다 guided>brute),
  함수의존성 큐도 버킷 분열로 기각됐음. **근본 해법 = 특징별 PMI 인식모델**(`SearchGuide`): 불연속
  서명 문자열 매칭 대신 **각 특징이 독립적으로 골격에 투표**(질의 특징들의 pointwise mutual information
  합). 다른 꿈꾼 절차군에서 배운 개별 특징(det:a·curv:up…)이 서명이 처음인 절차군에도 전이 →
  **외삽**; 특징 추가가 버킷을 분열 안 시킴(독립 투표). 기각했던 invariance 특징이 PMI에선 정식 채택.
  **실측: 3/3 HELP** — triangular 20→2, sq_b 22→20, bpow 90→65; 알려진 승리(mul 18→1, square 17→10)
  유지. 잠복버그 수리 동반(합성 basis None 전파). 전체 스위트 59/59, P0 불변. 사다리: F0~F4 + **F-next✓**.

## 불변식
1. 가이드는 **제안만** — 채택은 항상 held-out 검증게이트. 학습 오염이 알고리즘 오염이 될 수 없다.
2. dreaming 데이터는 자가생성 — 벤치 문항 절대 불가(시험-학습 금지 가드 유지).
3. 원장의 tombstone은 보존(왜 틀렸는지 감사 가능) — 오류는 지우는 게 아니라 배우는 것.
