# ATANOR Index — 자체 검색 인덱스 설계 (사장님 발의 2026-07-16)

> "외부 검색엔진 빌려다 쓰지 말고 perplexity 같은 검색인덱스를 우리 AI 아키텍처에 맞게 최적화한
> 검색엔진을 자체개발할 수 있어? … ATANOR Browser랑도 연결될 것 같고"

## 0. 정직한 스코프
- 웹 전체(구글급, 수천억 페이지·PB) 복제 = 불가(1PC 물리). **Perplexity의 실체도 자체 인덱스(웹의
  head) + 외부 API 폴백의 하이브리드** — 그 "자체 인덱스"는 우리 규모로 가능.
- 차별점: 빌린 엔진=링크+스니펫. **자체 인덱스=그래프-네이티브 증거**(패시지+추출 트리플+출처
  신뢰티어)를 반환 → 검색→접지→인용이 한 몸. 이것이 "ATANOR 최적화"의 실체.

## 1. 3-링 아키텍처
- **Ring 0 — PROPHETA (실재)**: world_pack 141.7M 트리플 + 영위키 패시지 685k. 이미 오프라인 인덱스.
- **Ring 1 — 큐레이트 크롤 인덱스 (빌드)**: 자체 크롤러 함대 없이 **Common Crawl(WET) 부분집합 +
  위키 전체(EN)+Simple+Wiktionary+StackExchange 덤프**로 부트스트랩. 목표 5~50M 패시지, 1~2TB.
  저장=디스크-백 역색인(memmap 포스팅, 우리 장기) + BM25 + referent resonance 재랭킹.
- **Ring 2 — ATANOR Browser = 분산 크롤러 (연결)**: 사용자 방문 페이지가 동의 하에 기존
  내용레인(공유)/행위레인(개인) 분리·DOM→그래프 증류(#102/#108/#166)·k-소스 합의·PII 격리 파이프를
  타고 공유 인덱스로. **봇 크롤 없이 사용자가 늘수록 인덱스가 자라는 네트워크 효과 해자.**
  법적으로도 깨끗(사용자 주도 브라우징; robots 크롤 논쟁 회피).

## 2. 기존 자산 매핑 (0이 아니라 60%에서 시작)

## 3. 숨은 보석 — 진짜 관련성 라벨
브라우저의 클릭·체류·재방문 = **실사용 관련성 신호**. 합성 데이터의 실전이-0 벽(2026-07-16 실측:
MCQ 판정기·수학 파서 모두 합성→실전이 실패)의 정확한 해독제. 학습 랭커는 이 **진짜 데이터**로만 훈련.

## 4. 단계와 게이트 (measure-don't-claim)
- **V0 (첫 스프린트) — ✅ SHIPPED 2026-07-16**: `packages/atanor_index/`.
  - `disk_index.py`: 디스크-백 BM25(Okapi k1=1.5 b=0.75). SPIMI **상위비트 버킷 외부병합**(버킷=hash
    상위비트→버킷순=해시순→전역정렬 유지, 피크 RAM=total/2^bits). 64비트 안정해시 키→오픈시 RAM 0(memmap).
  - `storage.py`: 외장하드 자동감지(2TB 밤도착)→ATANOR_Index/, 없으면 data/atanor_index 폴백.
  - `retriever.py`: local_search가 tavily/searxng 동일 웹 shape로 자체 패시지→provider 팬아웃 **1순위**.
    압도 필터(승자 score≥0.5×최고만 주입) — distractor 희석 방지.
  - **실측**: EN위키 full **7,016,505 패시지** 색인 = 4.82M terms · 333M postings · **539s**(RAM 5.6GB
    여유서 OOM 없이 버킷병합) · **1.8GB**(원본 4.1GB) · open 0.00s · **20ms/쿼리**. 정본 배터리
    **recall@10 14/14**(정본 문서 항상 top-10) · top-1 10/14(잔여 모호성=하위 엔티티앵커 재랭킹 몫).
  - **라이브**: 팬아웃 합류 후 Seoul 회귀 1건→압도필터로 수리. **인덱스 ON==OFF 확인**(orchestrate 답
    동일)=무회귀. 남은 웹배터리 실패(speed of light 값·boiling point 라우팅)는 인덱스와 무관한 기존
    컴포저/KG 문제(별개 트랙). 정직 결론: **검색 recall은 강함, 답 추출은 컴포저 몫**(설계대로 BM25=후보생성).
- **V1**: StackExchange+Common Crawl 큐레이트 서브셋(+1TB), 도메인 신뢰티어, 인덱스→그래프 증류 상시화.
- **V2**: Ring 2 연결(브라우저 증류→인덱스 인제스트), 클릭 신호 수집(개인정보=행위레인 로컬, 공유는
  익명 집계만) → 학습 랭커 v0.
- **V3**: 신선도 파이프(RSS+재크롤 큐), 자체-우선/외부-폴백 순서 역전.
