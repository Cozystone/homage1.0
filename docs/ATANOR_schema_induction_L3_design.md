# ATANOR L3 — 스키마 귀납 엔진: 법칙을 발명하는 층 (설계, 2026-07-22)

사장님: "남이 준 법칙이 아니라 법칙 자체를 발명하는 단계. 연구 더, 완벽 설계, 완벽 개발."
이 문서가 그 엔진의 캐노니컬 설계다 — 문헌에 접지하고, 우리 헌법(검증앵커·작화0)과 합친다.

## 0. 세 층위 (지금 위치)
- **L1 적용**: 준 스키마의 구멍만 채워 검증 → hard 5/10 (오늘).
- **L2 확장**: 사람이 법칙 가족 추가 → 8개 격파 시공 중.
- **L3 귀납(본 문서)**: **엔진이 검증된 풀이들에서 법칙을 추출·발명**. 유능함이 "얼마나 아느냐"→
  "모르는 문제에서 새 법칙을 만드느냐"로 전이. System-2(DELIBERATOR)의 심장, 초지능의 문턱.

## 1. 연구 접지 (실제 문헌, 정직 인용)

| 시스템 | 핵심 | 우리가 취하는 것 |
|---|---|---|
| **DreamCoder** (Ellis+ PLDI'21, R.Soc'23) | wake-sleep: solve→abstract(라이브러리 성장)→dream(신경검색 훈련). **압축=MDL**(최소기술길이): 좋은 추상=라이브러리+프로그램 총 기술길이를 줄이는 것. e-graph refactoring으로 공통 부품 발견 | ①wake-sleep 부트스트랩(풀수록 라이브러리 성장→더 어려운 문제) ②**MDL 압축을 추상 가치의 목적함수로** |
| **babble** (Cao+ POPL'23) | library learning modulo theory: e-graph+equality saturation+**anti-unification(최소일반화)**로 구문변형에 강인한 공통패턴 추출, DreamCoder보다 압축·속도 우위 | **anti-unification = 법칙 발명의 기계**(N개 구체풀이의 최소일반화=구멍뚫린 스키마) |
| **Leroy** (SPLASH'24 HATRA) | 명령형 Python: AST→Lisp화→Stitch 추출→**구현불가 추상 가지치기**→원언어 복원. 압축 1.04x(=프런티어, 미해결) | 명령형 파이프라인 형태(정규화→추출→가지치기→복원) + **정직한 기대치**(압축비는 승리지표 아님) |

**우리 델타 (헌법이 문헌을 넘는 지점)**: 문헌은 **압축(MDL)을 최적화**한다 — 압축되면 좋은 추상.
우리는 그 위에 **검증 게이트**를 얹는다: 발명된 스키마는 **재-인스턴스화해 격리 검증기를 통과**해
①자신을 낳은 풀이 ≥K개를 재현하고 ②미본 과제 ≥1개로 일반화할 때만 라이브러리 승격. **발명은 자유,
생존은 검증된 재현+일반화.** 이게 작화0 바닥을 "법칙 발명"에 적용한 것 — DreamCoder/babble엔 없는 층.
(Generative Leap Loop 독트린: 도약=표식, 단정=검증 뒤.)

## 2. 엔진 파이프라인

입력: `data/code_reason/library.jsonl`의 **검증된 풀이 코퍼스**(각각 격리검증 통과한 실제 Python 함수).

1. **정규화(Normalize)**: 각 풀이 AST → 정준형(α-리네이밍, 리터럴→구멍후보 표식, 제어구조 선형화).
   Leroy식 구조화된 S-형이되 우리 자체 IR 유지.
2. **Anti-unification(발명의 핵)**: 풀이들을 유사군으로 묶고 각 군의 **최소일반화(LGG, Plotkin)** 계산
   → 서로 다른 자리에 구멍이 뚫린 **후보 스키마**(=골격+구멍문법). babble식 e-graph는 v2, v1은 정규화
   AST 위 구조적 anti-unification(단순·충분).
3. **MDL 압축 랭킹**: 후보 스키마 s의 가치 = `Σ len(task_without_s) − [len(s) + Σ len(task_via_s)]`
   (양수=압축=유용). 압축이익 순 정렬. (DreamCoder 원리.)
4. **★검증 게이트(우리 바닥)**: 후보 s를 새 스키마로 취급(골격+구멍열거) → 격리검증기로
   ①유도원천 풀이 ≥K 재현 ②held-out 과제 ≥1 일반화 통과해야 승격. 실패=폐기(압축돼도 폐기).
   미검증 스키마는 절대 라이브러리 미유입.
5. **Wake-sleep 부트스트랩**: 풀기(wake)→풀이 코퍼스에서 스키마 귀납(abstract sleep)→풍부해진
   스키마로 다음 라운드 더 어려운 문제 풀기→반복. (신경검색 dream 단계는 v2=ACE 인코더 연동.)

## 3. ★결정적 실험 I3 — 정직 계측기 (문헌에 없는 우리 고유)
**Ablate-and-Reinvent**: 손으로 준 스키마 하나(예: DP-2D)를 `algorithm_schemas.py`에서 **제거** →
귀납 엔진을 (그 가족으로 풀렸던) 검증 풀이들에 돌림 → 엔진이 **DP-2D와 구조적으로 동치인 스키마를
스스로 재발명**해 edit_distance를 **다시 푸는가?** YES면 "법칙을 발명한다"가 수사가 아니라 **실측**.
falsifiable·깨끗함. (DreamCoder/babble은 이 실험을 명시 안 함 — 우리 정직 도구.)

## 4. 증분과 정직 게이트

| 증분 | 내용 | 통과 게이트 (정직) |
|---|---|---|
| I1 | 정규화 + 구조적 anti-unification 추출기 → 후보 스키마 발행 | 검증풀이 3개에서 **손으로 준 fold/count 가족을 엔진이 재발견** |
| I2 | MDL 랭킹 + 검증-게이트 승격 루프 (발명→재현K+일반화→승격/폐기) | 발명 스키마 ≥1개가 **사람이 안 준** 과제 검증 해결 |
| I3 | Ablation 재발명 실험(간단 가족부터: fold→count→DP-1D) | **뺀 법칙을 엔진이 재발명해 같은 과제 재해결**(1개 이상 가족) |
| I4 | mastery_v2 (라이브러리에 없는 은닉 신규 과제군) 재실측 | 귀납 기여분 정직 측정, **fail 0 유지** |

## 5. 정직한 스코프와 위험 (헌장)
- **프런티어다**: 명령형 라이브러리 러닝은 SOTA도 1.04x(Leroy). 우리 코퍼스는 작아 압축비는 낮을 것.
  **승리지표 = ①재발명 실험(I3) ②하드스키마 없이 새 과제 풀기** — 압축비 아님. 정직히 명시.
- **v1 목표는 단순 가족 재발명부터**: fold/map/count-dict, 가능하면 DP-1D. DP-2D·백트래킹 재발명은
  스트레치(깊은 구조) — 못 미치면 정직 기권 보고(오늘 8기권처럼).
- **작화 불가 불변**: 어떤 발명 스키마도 검증 통과 못 하면 폐기. 발명이 자유로워도 출고는 검증뿐.
- **뉴로 예산**: 이 엔진은 심볼릭(AST·anti-unif·검증) 위주 — 학습 컴포넌트 추가 시 뉴로 원장 등록.
