# Science E4 same-host isolation probe

This directory contains a deliberately narrow Docker probe for the future
independent science-E4 boundary.  For one observed local run it records whether
the declared same-host process, mount, network, privilege, and resource
controls passed.  Success appears only as
`gates.same_host_docker_isolation_gate_passed=true`; the authoritative
`claims` remain false.

It does **not** prove evaluator independence, external authenticity, benchmark
capability, E4, E5, or a resource-cost curve.

## Boundary

- `candidate/` and `evaluator/` are separate Docker build contexts.
- The candidate runs as numeric UID/GID `10001:10001`.
- The fixture evaluator runs as numeric UID/GID `10002:10002`.
- Both containers use `network=none`, a read-only root filesystem, all
  capabilities dropped, `no-new-privileges`, private PID/IPC namespaces,
  bounded CPU/memory/PID/file-descriptor resources, and a bounded `/tmp`
  `tmpfs`.
- A runner-owned sentinel and positive-control container share one internal
  bridge network.  The positive control must reach that sentinel; the
  candidate and evaluator receive the same sentinel endpoint through a
  read-only probe input but run with `network=none` and must fail to reach it.
  The same sentinel is rechecked before the candidate, between the candidate
  and evaluator, and after the evaluator.
- The candidate receives only a strict, gold-free request, a public fixture
  stage, and the network-probe endpoint, all read-only.
- The candidate never receives a Docker socket, evaluator code, gold fixture,
  or signing-key mount.
- The evaluator receives the candidate response, local gold fixture, and one
  ephemeral local HMAC key through exact read-only mounts.
- Container output is captured through stdout; there is no shared writable
  result volume.

The HMAC is intentionally named
`hmac-sha256-local-fixture-not-authority`.  Its key is generated by the same
host runner and is deleted with the temporary run directory.  It demonstrates
mount separation from the candidate, not external trust or durable
authentication; it is not production authority.

## Run

From the repository root:

```powershell
python -m deploy.science_e4_local.runner `
  --output reports/benchmarks/science_e4_local_isolation_v1.json
```

The runner builds two digest-bound images, proves that its reachable sentinel
control is discriminating, validates each isolated container's Docker inspect
policy before starting it, runs both one-shot containers, verifies the local
fixture HMAC, and writes a canonical manifest exclusively.

Candidate/evaluator build contexts and the runner are snapshotted before the
build, rebound after each build, and rebound again immediately before return.
Historical verification rederives the embedded request/response/evaluation
digests, source/image/inspect/mount/post-run bindings, signature structure,
network liveness count, and every gate; recomputing only the outer manifest
checksum cannot hide a nested edit.

The Docker probe leaves the two locally built images in the image cache but
fails closed unless its one-shot containers and internal bridge network are
removed.  It never pushes an image.

## Honest limitations

- The host user and Docker daemon administrator can inspect or alter both
  containers, mounts, images, and the ephemeral fixture key.
- Docker `network=none` removes external networking but retains an isolated
  loopback interface.
- Normalized `docker inspect` evidence is an assertion captured by this same
  host.  It is not remote attestation.
- `claims.os_isolation_established`,
  `claims.independent_evaluation_established`,
  `claims.canonical_e4_established`, and `claims.e5_established` remain false.
- Resource limits bound this probe; they do not establish a clean or reproducible
  resource curve on a shared host.
- A canonical independent E4 still requires an externally controlled examiner
  machine/codebase, hidden dataset and gold, signing key, nonce ledger, and
  detached receipt.
